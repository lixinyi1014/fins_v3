## 第一部分：代码逻辑与问题

### 1.1 整体结构

五个文件，职责分得很干净：

```
protocol.py   "协议是什么"：波特率/命令字符串/VOFA 16 通道/错误码位拆解，不发不收
link.py       "什么时候发"：串口收发线程 + 100 ms 心跳线程 + 断线重连 + 关闭时补 OFF
gamepad.py    手柄输入层：按键映射、死区、热插拔，掉线时所有输入归中位
hud.py        状态显示：严格区分"实测/设定/缺测"，缺测显示 "--" 并变红
joystick_control.py  把手柄输入翻译成命令 + 主循环
```

线程模型（三条线程 + 主循环）：

| 线程 | 周期 | 做什么 |
|---|---|---|
| `fins-hb` | 100 ms | 只发 `HB`。固件 500 ms 收不到就锁存停机 |
| `fins-rx` | 阻塞读 | 收字节 → 按 `\n` 切行 → `TelemetryParser` 更新状态；串口断了就每秒重连 |
| `fins-camera` | 取帧即刻 | 后台取帧，主循环只拿"最新一帧"，取不到就跳过，绝不等待 |
| 主循环 | 50 Hz | 收 pygame 事件 → 采样手柄 → 翻译成命令 → 画 HUD |

把心跳独立成线程是对的：老程序把心跳压在渲染循环里，摄像头一卡就被固件判掉线。

### 1.2 控制链路走向

```
手柄
 ├─ 十字键 ────────────→ W/S/A/D/Z      （离散锁存运动状态，固件开环预置 PWM）
 ├─ X/Y ──┬ ACL 关 ────→ Q/E            （离散旋转）
 │        └ ACL 开 ────→ 改 target_yaw → FSET
 ├─ A/B ──┬ 默认 ──────→ 改 target_depth → FSET:深度,横滚,俯仰,偏航
 │        └ --legacy-depth → UP/DN（每次 ±1 cm，10 Hz 连发）
 ├─ 摇杆 ──────────────→ MOT:a,b,c,d    （四路舵机，积分式，20 Hz 节流）
 ├─ Start ─────────────→ ON / OFF
 ├─ Back / 空格 ───────→ 急停：连发 3 次 OFF + 掐心跳 0.8 s
 └─ LB ────────────────→ ACL:ON / ACL:OF
```

三处我特别确认过、确实对的地方：

1. **VOFA 16 通道顺序**是压力四路在前、姿态深度在后（`VofaTelemetry.h` 确实如此）。
   按旧顺序解析会把压力当成姿态角显示且不报错，这份代码没踩。
2. **`ACL:OF`** —— 固件的白名单是 `{... "ACL:ON","ACL:OF","ACL:OFF"}`，三个都收。
3. **急停掐心跳 0.8 s** 触发的是 `StopCommandTimeout`，`fatal=false`，
   **不会**置 `safety_fault_latched`。也就是说急停之后按 R 复位再按 Start 就能重新解锁，
   不需要断电。（`TaskSharedState.cpp: CheckCommandTimeout`）

### 1.3 发现的问题

按严重程度排。

#### 【必须改】P1 — 手柄轴号是 pygame 1.x 时代的，右摇杆会接错，而且开机就有舵机跑到底

`gamepad.py` 的默认映射：

```python
"axes": {"left_horizontal": 0, "left_vertical": 1,
         "right_horizontal": 2, "right_vertical": 3}
```

pygame 2（SDL2）下 Xbox 手柄的真实轴号是：

| 轴 | 实际是什么 | 静止值 |
|---|---|---|
| 0 | 左摇杆 X | 0 |
| 1 | 左摇杆 Y | 0 |
| **2** | **左扳机 LT** | **−1.00** |
| 3 | 右摇杆 X | 0 |
| 4 | 右摇杆 Y | 0 |
| 5 | 右扳机 RT | −1.00 |

后果有两条，第二条会真的动硬件：

* 右摇杆完全接错：你推右摇杆左右，代码以为是"右摇杆上下"。
* **轴 2 静止读 −1.00**，绝对值 1.0 > 死区 0.25，又被 `invert` 翻成 +1.0，
  于是 `_update_servos` 里第四路（右下舵机）以 600 µs/s 的速度往上爬，
  **程序一启动、还没解锁，1.7 秒内右下舵机就顶到 2500 µs 死顶**。
  舵机不受停止锁存保护（固件里"停止只强制推进器中位，舵机保留原请求"），所以这是真动作。

按键号倒是对的（A=0,B=1,X=2,Y=3,LB=4,RB=5,Back=6,Start=7,LS=8,RS=9）。

**修法**：用我放在同目录的 `pad_probe.py` 探出你这只手柄的真实编号，
存成 `my_pad.json`，启动时加 `--mapping my_pad.json`。第二部分有详细步骤。

---

#### 【必须改】P2 — 压力四路的标签写反了，你会以为传感器坏了

`protocol.py` 第 252 行和 `hud.py` 第 156 行都写着：

> 四路 legacy 压力裸值，**空气中约 1000~1015**

这在"启动标定"做进去之前是对的。现在固件里（`Sensor.cpp`）：

```cpp
data_pressure[i] = LPF(data_pressure_raw[i] - data_pressure_offset[i]);
//                      当前读数          上电时测的空气基准
```

`data_pressure_offset` 在上电空气标定时被写成实测大气压，所以**空气中这四路读 ≈ 0.00，
不是 1000**。单位约等于 mbar，1 mbar ≈ 1.02 cm 水深，所以水下大致就是"深度的厘米数"。

HUD 上标着"空气中约 1000~1015"而实际显示 0.00，第一次上手一定会误判成传感器没读到。
这两处注释和 HUD 那行字得改。

---

#### 【建议改】P3 — 发了 ON 就认为解锁成功，没有等固件确认

`toggle_arm()` 里：

```python
self.link.parser.state.armed_reported = False
if self.link.send(Command.ARM):
    self.arm_intent = True     # 只要写进串口就算解锁
```

`armed_reported` 置 False 之后再没被读过。如果固件回
`CTRL=REJECT calibration_fault_or_stale_command` 或 `CTRL=REJECT feedback_not_ready`，
HUD 会显示「下位机 已停止 / 上位机意图 解锁」，你推杆没反应，只有控制台角落一行小字告诉你原因。

而且 `arm_intent` 是 `_send_motion` 和 `_flush` 的开关，状态不一致会让人很困惑。
建议：发 ON 后 0.5 s 内若 `stopped` 仍为 True，自动回滚 `arm_intent=False` 并提示。

---

#### 【建议改】P4 — `dt` 用的是标称值不是实测值

`update()` 里 `dt = 1.0 / CONTROL_HZ`（固定 0.02 s）。
主循环 `clock.tick(50)` 只是上限；开着摄像头、`smoothscale` 缩放 1080×660 的画面时，
实际很可能跑 30 Hz。那时深度/航向/舵机的变化速率全部只有标称值的 60%，
"按住 1 秒下潜 10 cm"就不成立了。改成记录上一帧 `now` 求真实 dt 即可。

---

#### 【小问题】

| 位置 | 问题 |
|---|---|
| `joystick_control.py:44` | 注释写"固件 vofa 名义 10 Hz，1.5 s 相当于连丢 15 行"。实际 `VOFA_PERIOD_S=0.02`（50 Hz），1.5 s 是 75 行。数值没错，注释过时 |
| `hud.py:198` | `self.small and TEXT` 是笔误，求值结果就是 `TEXT`，不影响显示但该写成 `TEXT` |
| `joystick_control.py` `_flush` | `_servo_dirty` 在"串口写成功"时清掉，不是"固件接受"时。若固件回 `FB=REJECT stale_command`（刚发生过一次停机、代次变了），舵机不会重发，HUD 显示的值和舵机实际位置就分叉了 |
| `protocol.py` | `Command.RECALIBRATE`（CA）、`TELEMETRY_ON/OFF`、`manual_thruster_command`（TES）、`MOTION_COMMANDS` 全是定义了没人用。尤其 CA：`toggle_arm` 失败时提示"需在空气中重新上电（CA）"，但界面上没有任何键能发 CA。而且固件收到 CA 只是锁存停止 + 回一句 `CAL=RESTART_AT_SURFACE`，**并不真的重新标定**（只在上电时标定），所以那句提示应该直接写"请断电重启" |
| 急停 | `emergency_stop` 不动舵机，四路舵机保持在最后位置。急停不等于全部归中位 |

## 第二部分：怎么接手柄、怎么操控

### 2.1 你需要准备什么

* 一只 **USB 有线** Xbox 手柄（第一次别用蓝牙，少一层变量）
* 下位机的 USB 转串口线（VOFA 用的那根就是，UART6 / 115200 / 8E1）
* Python 3.10 或更新

```bat
pip install pyserial pygame opencv-python
```

> 三个库都装不上再说，`opencv-python` 装不上可以先用 `--no-camera` 跑。

### 2.2 第一步：先确定串口号

手柄先别插，只插下位机：

```bat
cd C:\Users\lixin\Desktop\fins_joystick\fins_v3-main\joystick_controller
python joystick_control.py --list-ports
```

会列出类似：

```
可用串口：
  COM11  Silicon Labs CP210x USB to UART Bridge (COM11)
```

记下这个 `COM11`。**注意：VOFA 上位机和这个程序不能同时占用一个串口**，
跑之前先把 VOFA 关掉。

### 2.3 第二步：探出你这只手柄的真实编号（不能跳过）

这一步是为了绕开上面 P1 那个问题。手柄插上 USB，然后：

```bat
python pad_probe.py
```

弹出的窗口里：

1. **逐个按键**，屏幕上方会显示「按键 N 按下」。记下：
   A、B、X、Y、LB、RB、Back(View)、Start(Menu)、左摇杆按下、右摇杆按下 各是几号。
2. **慢慢推每根摇杆**，看"轴"那一栏哪个数字在变。记下：
   左摇杆左右 / 左摇杆上下 / 右摇杆左右 / 右摇杆上下 各是几号轴。
3. **看黄色警告行**：静止时数值就不是 0 的轴（一般是 LT/RT 两个扳机），
   这些轴号**绝对不能**填进摇杆映射里。
4. **推十字键**，确认 `hat0` 有反应，且上是 `(0, 1)`。
5. 按 ESC 退出，终端会打印一段 JSON 模板。

按你记下的编号把模板改好，存成同目录的 `my_pad.json`。典型的 pygame 2 + Xbox 手柄结果是：

```json
{
  "buttons": {
    "ascend": 0, "descend": 1, "yaw_ccw": 2, "yaw_cw": 3,
    "yaw_hold_toggle": 4, "fine_modifier": 5,
    "estop": 6, "arm_toggle": 7,
    "servo_left_center": 8, "servo_right_center": 9
  },
  "axes": {
    "left_horizontal": 0, "left_vertical": 1,
    "right_horizontal": 3, "right_vertical": 4
  },
  "hat": 0,
  "deadzone": 0.25,
  "invert": {
    "left_vertical": false, "left_horizontal": true,
    "right_vertical": true, "right_horizontal": true
  }
}
```

（注意 `right_horizontal` 从 2 改成了 3，`right_vertical` 从 3 改成了 4。）

### 2.4 第三步：干跑一遍（**推进器动力线必须是断开的**）

这一条没有商量余地：第一次跑，推进器的动力电源必须物理断开，
只给主控板供电。程序里的急停靠的是"串口还通"或"固件心跳超时"，
这两条在链路挂掉时都可能不成立，只有物理开关是可靠的。

```bat
python joystick_control.py --port COM11 --mapping my_pad.json --no-camera
```

窗口出来后，**先什么都别按**，对着左边的面板核对：

| 面板那一行 | 应该是什么 | 不对怎么办 |
|---|---|---|
| `链路 COM11 已连接` | 绿色 | 红色 = 串口号错了或被 VOFA 占着 |
| `遥测 xx ms 前 SEQ=...` | 灰色，SEQ 一直在涨 | 红色"从未收到" = 固件没在发 vofa 行 |
| `心跳 xx ms 前` | 绿色，小于 250 ms | —— |
| `状态 下位机 已停止 / 上位机意图 停止` | 正常，还没解锁 | —— |
| `反馈就绪 READY 是` | 绿色 | 红色见下面排查表 |
| `压力校准 CAL 是` | 绿色 | 红 = 上电时没在空气里静置，断电重来 |
| `锁存故障 FAULT 否` | 绿色 | 红 = 必须断电重启 |
| `四路压力` | 四个接近 **0.00** 的数 | 显示 `--` 才是真没读到（见 P2，0.00 是正常的） |
| `手柄 Xbox Controller` | 白色 | 红色"未连接" = 手柄没被 pygame 认出来 |

**重点看舵机那一栏**：四路应该稳定停在 `1500 us / +0.0°`，不动。
如果哪一路自己在涨或跌，说明 `my_pad.json` 里还有轴填错了，回到 2.3 重来。

然后推摇杆，看对应的那一路数字跟着动、松手就停住。四路对应关系：

| 摇杆动作 | 舵机 | HUD 标签 |
|---|---|---|
| 左摇杆 上下 | 第 1 路 | 左上 |
| 左摇杆 左右 | 第 2 路 | 左下 |
| 右摇杆 上下 | 第 3 路 | 右上（**固件会做 `3000−x` 反转**，HUD 会多显示一个"舵机实收"） |
| 右摇杆 左右 | 第 4 路 | 右下 |

按下左摇杆 = 第 1、2 路回中；按下右摇杆 = 第 3、4 路回中。
按住 RB 时步进减半（0.4 倍），用来微调。

### 2.5 第四步：解锁（现在有入水互锁）

> **2026-09-23 变更**：按 Start 不再立刻发 ON。ON 一到，固件就让四路垂直推进器
> 进入深度闭环，桨会转；空气中空转既无水冷也无负载。所以现在按 Start 只登记意图，
> 面板显示「上位机意图 **待入水**」，水压计读到 ≥ `--arm-depth`（默认 0.15 m）
> 才自动发 ON。再按一次 Start 取消；急停和链路断开也会取消。
> 台架断动力测试时用 `--arm-depth 0` 关掉互锁。
>
> 注意这层互锁**完全依赖深度零点是对的**。零点错了它要么永远不解锁，
> 要么在岸上就解锁。所以下水前必须先核对下面这条。

**核对标定零点**：面板「压力校准 CAL」下方现在会显示
`标定零点 101340 Pa（四路差 120 Pa）`。绝对值应当接近 **101325 Pa**；
偏离超过 3000 Pa（≈30 cm 水头）会变红并提示零点是在水里标的。
四路差应当接近 0，超过 1500 Pa 固件会直接判标定失败（CAL 红）。

确认 READY/CAL 全绿、FAULT 灭、标定零点正常，按 **Start**。

控制台会打印 `[控制] 已发 ON，保持深度 0.00 m，航向 xx.x°`，
面板上「下位机」应在一两个控制周期内从「已停止」变成「运行中」。

如果没变：

* 看控制台有没有 `CTRL=REJECT ...`
  * `calibration_fault_or_stale_command` → CAL 没过 / FAULT 已锁存 / 命令超过 500 ms 才被处理
  * `feedback_not_ready USE_STAT` → ESKF 还没收敛，等几秒再按
* 程序在 ON 被拒时会自动发一次 `EDIAG`，控制台会出现
  `[下位机] READY 未成立：IMU 帧无效`（或别的原因），照着那句话查

再按一次 Start 就是 OFF（上锁）。

### 2.6 完整按键表

| 输入 | 作用 | 发的命令 | 生效条件 |
|---|---|---|---|
| **Start** | 解锁 / 上锁 | `ON` / `OFF` | —— |
| **Back** | 急停 | `OFF`×3 + 掐心跳 0.8 s | 任何时候 |
| **空格**（键盘） | 同上 | —— | 任何时候 |
| **R**（键盘） | 急停复位 | —— | 急停后必须按，否则 Start 无效 |
| **ESC**（键盘） | 退出（退出时自动补 OFF） | —— | —— |
| 十字键 ↑ | 前进 | `W` | 已解锁 |
| 十字键 ↓ | 后退 | `S` | 已解锁 |
| 十字键 ← | 左移 | `A` | 已解锁 |
| 十字键 → | 右移 | `D` | 已解锁 |
| 松开十字键 | 停止水平运动 | `Z` | —— |
| **A** | 目标深度变浅 0.1 m/s | `FSET:...` | 已解锁 |
| **B** | 目标深度变深 0.1 m/s | `FSET:...` | 已解锁 |
| **X** | ACL 关：左转 / ACL 开：目标航向 −25°/s | `Q` 或 `FSET:...` | 已解锁 |
| **Y** | ACL 关：右转 / ACL 开：目标航向 +25°/s | `E` 或 `FSET:...` | 已解锁 |
| **LB** | 偏航闭环开关 | `ACL:ON` / `ACL:OF` | 任何时候 |
| **RB**（按住） | 舵机步进减半 | —— | —— |
| 左/右摇杆 | 四路舵机 | `MOT:` | **不需要解锁** |
| 按下左/右摇杆 | 对应两路舵机回中 | `MOT:` | —— |

水平运动是**锁存状态**：发一次 `W` 就一直前进，直到发 `Z`。
程序松开十字键会立刻发 `Z`，另外每 200 ms 重发一次当前状态防丢包。

深度默认是**绝对目标**模式（FSET）：按住 A/B 改的是目标深度，松手就停在那个深度。
加 `--legacy-depth` 会切回老的 `UP`/`DN` 每次 ±1 cm、10 Hz 连发。

### 2.7 第五步：带摄像头

```bat
python joystick_control.py --port COM11 --mapping my_pad.json --camera 0
```

画面没出来就换 `--camera 1`、`--camera 2` 试。
画面卡不会影响控制（取帧在独立线程），但会拉低主循环频率，进而影响 P4 那个 dt 问题。

### 2.8 第六步：才轮到接推进器

前面全部通过之后，再接动力。第一次接动力建议：

1. 机体**架空**（不下水、桨叶不碰任何东西）
2. 手放在物理总开关上
3. 只按 Start 解锁，**不推任何杆**，看八路有没有异常启动
4. 确认无误后再按一下 Start 上锁，然后才开始试运动

## 2.9 排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| `链路 断开，重连中` | 串口号错 / 被 VOFA 占用 / 线松 | `--list-ports` 重新确认，关掉 VOFA |
| `遥测 从未收到 vofa 行` | 固件没发 / 波特率或校验位不对 | 用 VOFA 或串口助手确认板子在发；本程序是 115200 **8E1**，不是 8N1 |
| 一启动就有舵机往一边跑 | 见 P1，扳机轴被当成摇杆 | 回 2.3 重做映射 |
| 四路压力显示 0.00 | **正常**，见 P2 | 标签写错了，不是传感器坏 |
| 四路压力显示 `--` | 压力帧无效 | 查 `EDIAG7` 的 `I2C2_ERR` / `P_FRAME_DROP` |

## 一句话安全提醒

这个程序的急停有两层：发 `OFF`（靠串口还通）和掐心跳（靠固件 500 ms 超时）。
两层都是软件的。**物理动力开关是第三层，也是唯一在链路彻底挂掉时还有效的一层，
任何一次试验都必须有人手放在上面。**
