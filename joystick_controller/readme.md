# fins_v3 手柄遥控上位机

配套固件：`Lower_Level_Controller`（V3.3 / RoboMaster C / ESKF + SI PID）。
协议依据 `Lower_Level_Controller/docs/CONFIG_AND_INTERFACES.md`。

> **安全前提**：固件文档明确写了「I2C 不能工作时无法保证停止 PWM 已写进去，
> 必须有独立动力切断手段」。本程序的急停依赖串口可达或心跳超时，
> **不能替代物理断电开关**。调试暂停时 IWDG 继续运行，断点不是急停。

## 零、固件版本对齐

本目录按 **`a69fbae`**（"解决了水压计读数，滤波问题"）的协议实现并验证。
以下几项在该提交被改过，改固件时必须同步改 `protocol.py`：

| 项目 | 当前值 | 对应位置 |
|---|---|---|
| VOFA 通道顺序 | 压力 0–3 在前，姿态/深度 4–7 在后 | `VOFA_FIELDS` |
| VOFA 频率 | 50 Hz（`LC_VOFA_PERIOD_US=20000`） | `VOFA_PERIOD_S` |
| 通道 14 | `ERROR_CODE`（原 `FLAGS`），按位打包 | `decode_error_code()` |
| 压力 0–3 单位 | legacy 裸值，**非米非 Pa**，空气中约 1000~1015 | `pressure_legacy` |
| 推进器中位 | 1550 µs，死区 1510–1610 | `THRUSTER_NEUTRAL_US` |

`test_protocol.py` 的 `test_vofa_field_order_regression` 专门锁住通道顺序：
按旧顺序解析**不会报错**，只会把压力值当姿态角显示，属于最危险的静默错误。
命令集（`ON`/`OFF`/`HB`/`FSET`/`MOT`/`ACL` 等）在该提交未变，新增了 `EDIAG`。

## 一、为什么不能直接用旧版手柄程序

旧版（`FinsROV-An-Underwater-Camera-Based-Multi-Robot-Platform/Code/Joystick_Control`）
在 fins_v3 上是**完全不工作**的，不是"效果差一点"：

| 旧版行为 | 在 fins_v3 上的后果 |
|---|---|
| `serial.send("ON")`，不带行尾 | 固件「不再接受没有行尾的 ON/OFF」，**每条命令都被丢弃** |
| 从不发送 `HB` | 固件 500 ms 无心跳即锁存停止，**根本无法解锁** |
| 无遥测读取 | 固件已提供 16 通道 VOFA 实测数据，旧版仍显示写死的 `currentDepth = 300` |

## 二、环境

```bash
conda create -n fins_v3 python=3.10
conda activate fins_v3
pip install pyserial pygame opencv-python
```

Python 3.12 及更高版本若装不上 `pygame`，改用 `pygame-ce`（接口兼容）。

## 三、运行

```bash
python joystick_control.py --list-ports          # 先查端口
python joystick_control.py --port COM11          # 正常启动
python joystick_control.py --port COM11 --no-camera
python joystick_control.py --port COM11 --legacy-depth   # 深度回退到 UP/DN
python joystick_control.py --port COM11 --mapping my_pad.json
```

端口不再硬编码。旧版把 `COM28` 写死且不检查 `open()` 返回值，
端口错了界面照常起来、每条命令静默失败；现在连不上会明确报错并后台重连。

## 四、操作映射

| 输入 | 功能 | 发出的命令 |
|---|---|---|
| Start | 解锁 / 停止（带前置检查） | `ON` / `OFF` |
| Back | **急停** | 连发 `OFF` + 掐断心跳 |
| 键盘 SPACE | 急停（手柄失灵时的兜底） | 同上 |
| 键盘 R | 急停复位 | — |
| 键盘 ESC | 退出（退出时必发 `OFF`） | `OFF` |
| 十字键 | 水平前后左右 | `W` / `S` / `A` / `D` / `Z` |
| A / B | 上浮 / 下潜 | `FSET:` 绝对深度（或 `UP`/`DN`） |
| X / Y | 偏航。闭环开时改目标航向，关时离散旋转 | `FSET:` 或 `Q`/`E` |
| LB | 偏航闭环开关 | `ACL:ON` / `ACL:OF` |
| RB（按住） | 舵机微调，步进降到 40% | — |
| 左/右摇杆 | 四路舵机 | `MOT:a,b,c,d` |
| 左/右摇杆按下 | 对应两路舵机归中 | `MOT:` |

手柄编号因设备而异，用 `--mapping` 指定 JSON 覆盖 `gamepad.py` 里的
`DEFAULT_MAPPING` 即可，未映射的按键会在日志里提示编号。

## 五、解锁流程

固件的 `ON` 会在校准未过、反馈未就绪、已锁存故障或命令过期时被拒绝。
本程序在发 `ON` 之前先自查，避免操作者面对一句无上下文的 `CTRL=REJECT`：

1. 串口已连接，且有新鲜的 `vofa` 遥测（≤1 s）。
2. `CAL=1` 压力校准通过。
3. `FAULT=0` 无锁存故障。
4. `READY=1` 反馈可用。
5. 用**实测深度和航向**初始化目标值，再发 `ON`。

任一条不满足就不发 `ON`，并在日志里说明原因、自动补发一次 `STAT`。

## 七、解决了旧版哪些缺陷

### 链路与协议

1. **命令行尾**：`protocol.encode()` 统一补 CRLF，并校验长度 ≤99 字符、
   无非法字节、不自带行尾。整行一次 `write` 写出，满足固件 250 ms 成行要求。
2. **心跳**：独立线程按 100 ms 发 `HB`，不受渲染或摄像头阻塞影响。
   自测验证主循环卡死 0.6 s 期间心跳照常。
3. **发送失败可见**：`send()` 返回值被检查，失败即计数并断开重连，
   HUD 上直接显示失败次数与重连次数。旧版 `except: return False` 无人过问。
4. **断线重连**：接收线程发现串口失效后每秒重试，不必重启程序。

### 安全

5. **急停**：Back 键或空格连发 `OFF`，同时**主动暂停心跳 0.8 s**，
   即使 `OFF` 因链路故障没送达，固件 500 ms 心跳超时也会强制停止。
   急停被锁存，必须按 R 显式复位才能再次解锁。
6. **退出必停机**：`try/finally` 保证任何退出路径（正常、异常、Ctrl+C）
   都发 `OFF` 并关闭串口。旧版崩溃时潜器保持最后的运动状态。
7. **手柄掉线即停**：检测到掉线立即发 `Z` 并把所有输入视为中位，
   旧版会因未捕获异常直接崩掉。
8. **解锁前置检查**：见上一节，避免在未校准或有故障时盲目发 `ON`。
9. **上位机侧看门狗**：解锁后遥测中断超过 1.5 s 即自主停机。
   这补的是固件察觉不到的失效 —— 串口 TX/RX 是两根独立的线，
   下行断掉（或本机接收线程卡死）时，心跳仍正常发出、
   固件反馈自检全部通过，潜器会带着最后的目标继续运行，
   而操作者已经看不到任何实测值。这种"盲飞"只能由上位机自己终止。
   处理方式与急停一致：发 `OFF` + 暂停心跳 + 锁存，须按 R 复位。

### 反馈

10. **真实遥测**：解析 16 通道 `vofa` 行，HUD 显示下位机 ESKF 的实测深度、
    横滚、俯仰、航向和四路压力。旧版显示写死的 `300` 且从不更新。
    四路压力标注为"legacy 裸值，非米" —— 固件直接发旧 `data_pressure[]`，
    空气中约 1000~1015，不经 Pa/米换算，标成深度会误导操作者。
11. **缺测与过期可辨**：固件的 `-9999` 显示为 `--`，
    遥测超过 1 s 未更新则整块变红并提示"显示值不可信"。
12. **停止原因**：解析 `WHY` 并翻译成中文（心跳超时 / 反馈无效 / 周期超时 …）。
    停止原因同时从 `vofa` 的 `ERROR_CODE` 低 8 位取，50 Hz 连续上报，
    比 1 s 一次的 `STAT` 更及时；8~15 位的 I2C2 累计错误也一并显示。
    `ON` 被拒时自动发 `EDIAG`，用 `EDIAG1` 的 `NR` 掩码直接说明
    是哪个 `READY` 条件没过，不用操作者对着 `STAT` 猜。
13. **拒绝回执**：`CTRL=REJECT` 和 `FB=REJECT` 直接打到日志区。
14. **周期诊断**：`DIAG` 每 5 s 一次，显示控制耗时、峰值、超期、丢包、
    I2C 错误和温度。

### 控制

15. **深度改为绝对目标**：默认用 `FSET` 一次提交深度/横滚/俯仰/偏航，
    按住 A/B 以 0.1 m/s 连续改目标深度。旧版 `UP`/`DN` 是边沿触发，
    每按一次只动 1 cm，必须连点。`--legacy-depth` 可回退。
16. **偏航闭环可达**：LB 切 `ACL:ON`/`ACL:OF`。旧版固件支持但手柄发不出来。
    闭环开启时 X/Y 改的是目标航向，并在开启瞬间用实测航向同步本地设定值，
    避免本地陈旧的 yaw 通过 `FSET` 和 `ACL` 打架。
17. **舵机限幅统一**：四路都是 500–2500 µs。旧版两路被卡在 1000–2000、
    两路 500–2500，且正负号一路与其余三路相反。
18. **第三路反转可见**：固件 `Servo_I2C::data_extract` 对第三路做 `3000-x`，
    HUD 同时显示"发出值"和"舵机实收值"。旧版 HUD 显示的是发出值，
    与舵机实际角度不符，还把四路标成了水平/垂直（实际是上/下）。
19. **发送节流**：运动状态变化时立即发，之后 200 ms 周期重发以抗丢包，
    不再 30 Hz 刷屏。稳态峰值约 46 命令/秒，远低于链路上限，
    也不会冲垮固件只有 8 格的接收队列。

### 工程

20. **控制与渲染解耦**：摄像头取帧移到独立线程，主循环 50 Hz
    （旧版 30 Hz 且被 USB 取帧阻塞拖慢）。取不到帧就跳过渲染，不等待。
21. **手柄只初始化一次**：旧版每帧重建 `Joystick(0)` 并 `init()`。
22. **画面完整**：按比例缩放进显示区。旧版把 640 高的帧塞进 480 高的窗口，
    下半部分被裁掉。
23. **按键映射可配置**：`--mapping` 支持不同手柄，死区从 0.5 降到 0.25。

## 八、已知限制

- **水平移动仍是离散状态**，速度由固件的 `state_PWM_map` 查表决定，
  摇杆幅度不影响推力。固件没有连续水平速度接口，
  只有 `TES:` 手动八路 PWM，而它要求闭环关闭，不适合常规驾驶。
- **横滚/俯仰目标固定为 0°**（保持水平）。需要主动姿态可改
  `Controller.target_roll_deg` / `target_pitch_deg`，范围 ±30°。
- **`TES:` 未接到按键上**。协议层已实现 `manual_thruster_command()`，
  但手动八路 PWM 属于调试手段，误触风险高，故不绑定手柄。
- 急停与退出停机都**依赖串口或心跳超时**，见文首安全前提。
- 自测覆盖协议、链路、解锁和停止逻辑，**不证明实机时序、接线和水下稳定性**。
